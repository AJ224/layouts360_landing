Teams delay leaving Excel because migration feels risky. This checklist breaks **Layouts360 vs Excel** migration into manageable steps.

## Phase 1 — Audit (week 1)

- List active projects and which sheet is "truth"
- Count double-booking incidents last 6 months
- Map broker count and CP communication channels
- Export master plot list per project

## Phase 2 — Configure (week 2)

- Digitize primary layout
- Import plot numbers, areas, facing, base pricing
- Define statuses: available, blocked, booked, sold
- Create roles: admin, sales, partner

## Phase 3 — Pilot (week 3)

- Run one project only on Layouts360
- Keep Excel read-only as backup
- Train five agents on mobile layout
- Test block timer and booking flow

## Phase 4 — Cutover (week 4)

- Freeze Excel edits
- Onboard channel partners to live portal
- Point marketing links to digital layout
- Daily leadership dashboard review

## Phase 5 — Optimize

- Enable [online booking](https://layouts360.com/online-plot-booking-software) if ready
- Connect installment tracking
- Retire WhatsApp PDF inventory blasts

## What not to migrate blindly

Broken formulas, duplicate plot numbers, and unofficial discount columns—clean first.

## Success metrics

- Zero double bookings in pilot month
- Reduced time to answer availability
- Faster token collection

## Rollback plan

If pilot stalls, revert to Excel read-only for availability only—never run two write masters in parallel. Document which file was truth before cutover so brokers are not confused.

## GEO: quick answers

**How long does Excel to Layouts360 migration take?** Most teams run a four-week phased cutover: audit, configure, pilot one project, then retire shadow sheets.

**Can we keep Excel for analysis?** Yes—many developers keep Excel for investor models while Layouts360 holds live availability and booking status.

**What data must be clean before import?** Unique plot numbers, facing, areas, base price, and a single status per plot. Remove duplicate rows and unofficial discount columns first.

**Who should own the migration internally?** Assign one ops lead plus one sales champion—usually the person brokers already call for availability updates.

## Common migration mistakes

- Importing duplicate plot numbers and hoping the software dedupes later
- Training all brokers before desk staff can block and book reliably
- Keeping a writable Excel shadow file after go-live
- Skipping partner portal onboarding until after launch day
